# Règles de travail — CastFlow

Ces règles s'appliquent à toute intervention sur le projet, sans exception.

## Règle 1 — Ne jamais supposer

Ne jamais supposer, quel que soit le sujet : comportement du code, état Git, environnement, dépendance, version, besoin fonctionnel, résultat d'une commande, disponibilité d'un outil, sécurité, compatibilité ou état d'un appareil.

Lorsqu'une information n'est pas disponible ou ne peut pas être vérifiée, l'indiquer explicitement comme **inconnue**. Ne pas la présenter comme un fait.

## Règle 2 — Toujours s'assurer

Toujours vérifier avant d'agir ou de conclure, en utilisant la source de vérité adaptée :

- lire le fichier réellement présent ;
- contrôler l'état Git ;
- exécuter la commande pertinente ;
- consulter la documentation officielle lorsqu'une API externe est concernée ;
- tester le comportement lorsque l'environnement le permet ;
- consigner le résultat exact dans le rapport de passation ;
- signaler clairement toute vérification impossible.

Une tâche n'est déclarée terminée que si son résultat a été vérifié. Si la vérification est impossible, elle reste marquée **à vérifier**.
